Golang Concurrency Goroutine Leaks Testing

Every goroutine needs an exit.

The risk

Goroutines nobody waits for

Golang, compiles and runs code that never waits for its goroutines! This is what goroutine leak means.

main.go 
package main

import "fmt"

func notify() {
    ch := make(chan string)
    go func() {
        // Blocks forever: no receiver
        ch <- "done"
    }()
}

func main() {
    notify()
    fmt.Println("All good?")
}

The safeguards

Catch leaks in your tests with goleak

goleak reports goroutines still running when the check happens. An unwaited goroutine that finishes in time goes unnoticed.
goleak.VerifyNone

Fails a single test if extra goroutines are still running when it ends. Note: it does not work with t.Parallel.

notify_test.go 

func TestNotify(t *testing.T) {
    defer goleak.VerifyNone(t)
    notify()
}
goleak.VerifyTestMain

Checks once after all tests in the package have passed. Use it for parallel tests.

main_test.go 

func TestMain(m *testing.M) {
    goleak.VerifyTestMain(m)
}

Takeaway

Wait for your goroutines. Verify with goleak.

Install it with go get -t go.uber.org/goleak. Docs: https://github.com/uber-go/goleak
