Event Loop

Posts

Click through the phases. "Next" from the last phase wraps back to the first, that's the loop. Before the loop advances past any callback, not just once per phase, but after every single callback returns Node drains nextTick, then Promise microtasks. A phase with five queued callbacks means five separate microtask drains, one after each.

🔒 What goes in the close queue?

The close queue is the final phase of the Node.js event loop. It holds callbacks that are invoked when a resource is closed. These are typically registered via .on('close', ...) or the callback passed to .close(...).

🖥 Server
  • server.close(callback)
  • server.on('close', cb)
🔌 Socket / Stream
  • socket.on('close', cb)
  • stream.on('close', cb)
👶 Child Process
  • child.on('close', cb) - emitted when the child process has terminated
⏳ When? The close queue runs after the check queue (setImmediate) and before the event loop restarts. Microtasks (nextTick & Promise) are drained after every phase, including after the close queue.

Run the demo with the probe preloaded to see each log line annotated with the loop iteration and the phase.

event-loop-demo.js (main script) 
const fs = require('fs');
const http = require('http');

console.log('=== Event Loop Order ===\n');

// -------- Close queue --------
const server = http.createServer((req, res) => res.end('OK'));
server.on('close', () => {
  console.log('8. [Close] server closed');
});

server.listen(0, () => {
  console.log(`Server listening on port ${server.address().port}`);
  setImmediate(() => {
    console.log('Closing server...');
    server.close();
  });
});

// -------- 1. Microtasks (nextTick) --------
process.nextTick(() => {
  console.log('1. [Micro] nextTick');
});

// -------- 2. Microtasks (Promise) --------
Promise.resolve().then(() => {
  console.log('2. [Micro] Promise');
});

// -------- 3. Timer queue --------
setTimeout(() => {
  console.log('3. [Timer] setTimeout 0ms');
}, 0);

// -------- 4. I/O queue --------
fs.readFile(__filename, () => {
  console.log('4. [I/O] fs.readFile');
});

// -------- 5. Check queue --------
setImmediate(() => {
  console.log('5. [Check] setImmediate');
});

// -------- Microtasks between phases --------
setTimeout(() => {
  process.nextTick(() => console.log('   [Micro] nextTick (after timer)'));
  Promise.resolve().then(() => console.log('   [Micro] Promise (after timer)'));
}, 0);

fs.readFile(__filename, () => {
  process.nextTick(() => console.log('   [Micro] nextTick (after I/O)'));
  Promise.resolve().then(() => console.log('   [Micro] Promise (after I/O)'));
});

setImmediate(() => {
  process.nextTick(() => console.log('   [Micro] nextTick (after check)'));
  Promise.resolve().then(() => console.log('   [Micro] Promise (after check)'));
});

server.on('close', () => {
  process.nextTick(() => console.log('   [Micro] nextTick (after close)'));
  Promise.resolve().then(() => console.log('   [Micro] Promise (after close)'));
});
probe-iter.js (preload with -r) 
// Annotates every log line with loop iteration + phase
const async_hooks = require('async_hooks');
const types = new Map();

async_hooks.createHook({
  init(id, type) { types.set(id, type); }
}).enable();

let iter = 0;
// a "sentinel" immediate re-armed every iteration marks each check phase
(
  function mark() {
    iter++;
    const im = setImmediate(mark);
    im.unref && im.unref();
  }
)();

iter = 0;

const PHASE = {
  Timeout: 'TIMER phase',
  Immediate: 'CHECK phase',
  FSREQCALLBACK: 'POLL phase (I/O)',
  TickObject: 'nextTick drain',
  PROMISE: 'microtask drain'
};
const orig = console.log.bind(console);

console.log = (...a) => {
  const t = types.get(async_hooks.executionAsyncId()) || 'sync';
  orig(`[iter ${iter}] [${(PHASE[t] || t).padEnd(17)}] ${a.join(' ')}`);
};

🧠 Why iter 3 for I/O?

The sentinel setImmediate increments iter on every check phase. The file read completes asynchronously and its callback is placed in the I/O queue. Because the file isn't ready during the first Poll phase (iter 0), the loop progresses to Check (iter 1) and Close. Once the file is read (which happens in the background), the callback is picked up in the next Poll phase, which is iter 3 (iter 2 would be the Poll phase where no I/O was ready again, so it moved on).

This is what we meant by "Microtasks (nextTick & Promise) are drained after every phase, including after the close queue"
